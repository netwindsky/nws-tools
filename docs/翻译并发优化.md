# 翻译并发优化

## 问题描述

**现象**：
后台模型已经配置 `parallel: 8`（同时处理 8 个请求），但前端翻译仍然是一个一个串行执行的。

**根本原因**：
`PageManager.processElement` 使用了 `async/await`，导致每个元素的翻译必须等待完成后才开始下一个。

```javascript
// 修复前：串行执行
async processElement(element) {
    // ... 准备文本 ...
    
    try {
        const translation = await this.module.translateText(fullText);  // ← 等待完成
        // ... 应用翻译 ...
    } catch (e) {
        // ... 错误处理 ...
    }
}
```

即使 `TranslationModule` 内部有队列系统（`concurrentLimit: 8`），但 `PageManager` 是**串行调用** `translateText` 的。

---

## 调用链分析

### 修复前的调用流程

```
processElements() 扫描页面
  ↓
发现元素1 → processElement(元素1)
  ↓
await this.module.translateText(文本1)  ← 等待完成
  ↓
发现元素2 → processElement(元素2)
  ↓
await this.module.translateText(文本2)  ← 等待完成
  ↓
发现元素3 → processElement(元素3)
  ↓
await this.module.translateText(文本3)  ← 等待完成
  ↓
...
```

**问题**：每个翻译请求必须等待前一个完成后才开始，即使后台可以并发处理 8 个。

### 修复后的调用流程

```
processElements() 扫描页面
  ↓
发现元素1 → processElement(元素1)
  ↓
this.module.translateText(文本1).then(...)  ← 不等待，直接返回
  ↓
发现元素2 → processElement(元素2)
  ↓
this.module.translateText(文本2).then(...)  ← 不等待，直接返回
  ↓
发现元素3 → processElement(元素3)
  ↓
this.module.translateText(文本3).then(...)  ← 不等待，直接返回
  ↓
...
  ↓
TranslationModule 队列系统并发处理
  ↓
同时处理 8 个请求
```

**改进**：所有翻译请求立即提交到队列，由 `TranslationModule` 并发处理。

## 修复方案

### 方案 1：移除 async/await，使用 Promise

**修改 `PageManager.processElement`**：

```javascript
// 修复前
async processElement(element) {
    // ... 准备文本 ...
    
    try {
        const translation = await this.module.translateText(fullText);
        // ... 应用翻译 ...
    } catch (e) {
        // ... 错误处理 ...
    }
}

// 修复后
processElement(element) {
    // ... 准备文本 ...
    
    // 不等待翻译完成，直接返回，让 TranslationModule 的队列系统并发处理
    this.module.translateText(fullText)
        .then((translation) => {
            // ... 应用翻译 ...
        })
        .catch((e) => {
            // ... 错误处理 ...
        });
}
```

**关键改进**：
- ✅ 移除 `async` 关键字
- ✅ 使用 `.then()` 和 `.catch()` 替代 `await`
- ✅ 不等待翻译完成，立即返回
- ✅ 所有请求并发提交到队列

### 方案 2：修改默认并发配置

**修改 `TranslationModule` 默认配置**：

```javascript
// 修复前
defaultConfig: {
    // ...
    concurrentLimit: 1,  // 默认只并发 1 个
    // ...
}

// 修复后
defaultConfig: {
    // ...
    concurrentLimit: 8,  // 默认并发 8 个请求
    // ...
}
```

**关键改进**：
- ✅ 默认并发数从 1 改为 8
- ✅ 与后台模型配置保持一致

## 并发处理流程

### TranslationModule 队列系统

```javascript
class TranslationModule {
    constructor() {
        this.queue = [];           // 待处理队列
        this.activeRequests = 0;   // 当前活跃请求数
        this.config.concurrentLimit = 8;  // 并发限制
    }
    
    translateText(text) {
        // 提交到队列
        return this.enqueueTranslation(text);
    }
    
    enqueueTranslation(text) {
        return new Promise((resolve, reject) => {
            // 加入队列
            this.queue.push({ text, resolve, reject });
            // 触发队列处理
            this.processQueue();
        });
    }
    
    processQueue() {
        const limit = this.config.concurrentLimit;  // 8
        
        // 当活跃请求数 < 限制 且 队列不为空时，继续处理
        while (this.activeRequests < limit && this.queue.length > 0) {
            const task = this.queue.shift();
            this.activeRequests += 1;
            
            // 执行翻译
            this.translateTextRequest(task.text)
                .then((result) => {
                    this.activeRequests -= 1;
                    task.resolve(result);
                    this.processQueue();  // 递归处理下一个
                })
                .catch((error) => {
                    this.activeRequests -= 1;
                    task.reject(error);
                    this.processQueue();  // 递归处理下一个
                });
        }
    }
}
```

### 并发处理示例

假设页面有 20 个元素需要翻译：

```
时间线：

T0: 提交请求 1-8   (active: 8, queue: 12)
T1: 请求 1 完成     (active: 7, queue: 12) → 开始请求 9
T2: 请求 2 完成     (active: 7, queue: 11) → 开始请求 10
T3: 请求 3 完成     (active: 7, queue: 10) → 开始请求 11
...
T10: 请求 8 完成    (active: 7, queue: 4)  → 开始请求 16
...
T15: 所有请求完成

vs 串行处理（修复前）：

T0: 开始请求 1      (active: 1)
T2: 请求 1 完成     → 开始请求 2
T4: 请求 2 完成     → 开始请求 3
...
T40: 所有请求完成
```

**性能提升**：从 40 个时间单位减少到 15 个，**提升约 62.5%**。

## 代码变更

### 文件 1: PageManager.js

**修改 `processElement` 方法**：

```javascript
// 移除 async 关键字
processElement(element) {
    // ... 准备文本 ...
    
    // 不等待翻译完成，直接返回
    this.module.translateText(fullText)
        .then((translation) => {
            if (translation && this.isObserving) {
                const mode = this.module.config.translationMode || 'bilingual';
                if (mode === 'bilingual') {
                    this.view.applyBilingualTranslation(element, translation);
                } else {
                    this.view.applyBilingualTranslation(element, translation);
                }
            }
        })
        .catch((e) => {
            console.warn('[PageManager] Translation failed for element:', element, e);
        });
}
```

## 注意事项

### 1. 错误处理

使用 `.catch()` 替代 `try/catch`，确保错误不会阻塞其他请求：

```javascript
this.module.translateText(fullText)
    .then((translation) => { /* ... */ })
    .catch((e) => {
        console.warn('[PageManager] Translation failed:', element, e);
        // 错误不影响其他并发请求
    });
```

### 2. 内存管理

并发请求会增加内存使用，确保：
- 后台模型有足够内存处理 8 个并发请求
- 浏览器不会内存溢出

### 3. 网络带宽

并发请求会增加网络带宽使用：
- 确保网络带宽足够
- 避免因并发过高导致请求超时

### 4. 后台模型限制

确保后台模型真正支持 `parallel: 8`：
- 检查 Ollama 配置
- 检查模型加载参数
- 监控 GPU/CPU 使用率
