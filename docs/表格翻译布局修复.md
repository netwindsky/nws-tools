# 表格翻译布局修复

## 问题描述

**现象**：
翻译表格时，整个表格的单元格内容都被压缩成一列，破坏了表格结构。

**原始布局**：
```
┌─────────────┬─────────────┬─────────────┐
│   Agent     │  Specialty  │ When to Use │
├─────────────┼─────────────┼─────────────┤
│ UI Designer │ Visual ...  │ ...         │
└─────────────┴─────────────┴─────────────┘
```

**错误的翻译后布局**：
```
┌─────────────────────────────┐
│ Agent                       │
│ UI 设计师                    │
├─────────────────────────────┤
│ Specialty                   │
│ 视觉设计、组件库、设计系统     │
├─────────────────────────────┤
│ When to Use                 │
│ 何时使用                    │
└─────────────────────────────┘
```

整个表格从 3 列变成了 1 列！❌

---

## 根本原因

### 之前的修复方案

**双语包裹器样式**：
```css
.nws-bilingual-wrapper {
    display: grid !important;
    grid-template-columns: 1fr !important;  /* ← 强制 1 列 */
    grid-template-rows: auto auto !important;
    gap: 8px !important;
    margin: 8px 0 !important;
    width: 100% !important;
}
```

**问题**：
- `display: grid` + `grid-template-columns: 1fr` 强制所有子元素变成**单列布局**
- 对于普通文本块，这是正确的（强制垂直布局）
- 但对于**表格单元格**，这会破坏表格的列结构

### 为什么会这样？

**HTML 结构**：
```html
<table>
  <tr>
    <td>
      <div class="nws-bilingual-wrapper">  <!-- ← 问题在这里 -->
        <span>UI Designer</span>           <!-- 原文 -->
        <div class="nws-translation-style">
          <span>UI 设计师</span>            <!-- 译文 -->
        </div>
      </div>
    </td>
    <td>Visual design...</td>
    <td>...</td>
  </tr>
</table>
```

**CSS 影响**：
```css
.nws-bilingual-wrapper {
    display: grid !important;  /* 覆盖 td 的 display: table-cell */
    grid-template-columns: 1fr; /* 强制变成 1 列 */
}
```

**结果**：
- `<td>` 内的 `.nws-bilingual-wrapper` 被强制变成 grid 布局
- grid 的宽度是 `1fr`（100% 单元格宽度）
- 表格的列结构被破坏，所有单元格都变成单列垂直排列

---

## 修复方案

### 核心思路

**区分表格内外的翻译元素**：
- **表格外**：使用 grid 布局，强制垂直排列
- **表格内**：使用 block 布局，保持表格结构

### 实现步骤

#### 1. 检测是否在表格中

```javascript
applyBilingualTranslation(element, translatedText) {
    // 检查是否在表格中
    const isInTable = element.closest('table, td, th, tbody, thead, tr') !== null;
    
    // 创建 wrapper
    wrapper = document.createElement('div');
    wrapper.className = 'nws-bilingual-wrapper';
    
    // 在表格中，添加特殊类名
    if (isInTable) {
        wrapper.classList.add('nws-bilingual-wrapper-table');
    }
    
    // ... 其他逻辑
}
```

**检测逻辑**：
```javascript
element.closest('table, td, th, tbody, thead, tr')
```

向上查找最近的表格相关元素，如果找到说明在表格中。

#### 2. 新增表格专用样式

```css
/* 表格内的双语包裹器：使用 block 布局，保持表格结构 */
.nws-bilingual-wrapper-table {
    display: block !important;
    width: 100% !important;
    margin: 0 !important;
}

/* 译文样式 */
.nws-bilingual-wrapper-table > .nws-translation-style {
    display: block !important;
    margin-top: 4px !important;
    padding-top: 4px !important;
    border-top: 1px solid rgba(255, 255, 255, 0.1) !important;
}
```

**关键点**：
- `display: block`：不改变父元素 `<td>` 的 `table-cell` 布局
- `width: 100%`：占满整个单元格
- `margin: 0`：不添加额外边距，避免撑大单元格
- 译文使用 `block` + 分隔线，清晰区分原文和译文

## 技术细节

### 1. 表格检测范围

```javascript
element.closest('table, td, th, tbody, thead, tr')
```

**检测的元素**：
- `table` - 表格根元素
- `td` - 单元格
- `th` - 表头单元格
- `tbody` - 表格主体
- `thead` - 表格头部
- `tr` - 表格行

**只要元素在这些标签内，就会被识别为表格内**。

### 2. 样式优先级

```css
/* 通用样式 */
.nws-bilingual-wrapper {
    display: grid !important;
}

/* 表格内特殊样式（优先级更高） */
.nws-bilingual-wrapper-table {
    display: block !important;
}
```

**优先级**：
- `.nws-bilingual-wrapper-table` 比 `.nws-bilingual-wrapper` 更具体
- 即使都使用 `!important`，更具体的选择器优先级更高

### 3. 视觉分隔

**表格内**：
```css
.nws-bilingual-wrapper-table > .nws-translation-style {
    border-top: 1px solid rgba(255, 255, 255, 0.1) !important;
}
```

使用**细线分隔**，在有限的单元格空间内清晰区分原文和译文。

**表格外**：
```css
.nws-bilingual-wrapper {
    gap: 8px !important;
}
```

使用**间距分隔**，有足够的空间展示双语对照。

## 边界情况

### 1. 表格外的 inline 元素

```html
<div>
  <span>UI Designer</span>
</div>
```

**检测**：
```javascript
element.closest('table, td, th, ...') → null
```

**结果**：使用普通 grid 布局 ✅

### 2. 表格内的块级元素

```html
<table>
  <tr>
    <td>
      <div>
        <p>UI Designer</p>
      </div>
    </td>
  </tr>
</table>
```

**检测**：
```javascript
element.closest('td') → <td> 元素
```

**结果**：使用表格专用布局 ✅

### 3. 动态添加的表格

```javascript
// 动态添加表格
const table = document.createElement('table');
table.innerHTML = '<tr><td>UI Designer</td></tr>';
document.body.appendChild(table);
```

**检测**：
- 翻译时 `element.closest('td')` 能找到
- 正确应用表格专用样式 ✅

## 性能影响

### 检测开销

```javascript
const isInTable = element.closest('table, td, th, tbody, thead, tr') !== null;
```

**性能分析**：
- `closest()` 是原生 DOM API，性能优秀
- 最多向上遍历 6 种标签（table, td, th, tbody, thead, tr）
- 通常在 2-3 层内就能找到结果

**总体影响**：**可忽略不计**（纳秒级别）

### 样式影响

**新增 CSS 规则**：
- 2 条新规则
- 只在表格内元素上应用
- 不影响其他元素

**总体影响**：**无性能影响**

## 总结

### 修复内容

1. ✅ **表格检测**
   - 使用 `closest()` 向上查找表格元素
   - 支持所有表格相关标签

2. ✅ **区分样式**
   - 表格外：`display: grid`（强制垂直）
   - 表格内：`display: block`（保持结构）

3. ✅ **视觉优化**
   - 表格内：细线分隔
   - 表格外：间距分隔

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 表格翻译 | ❌ 变成一列 | ✅ 保持结构 |

| 复杂表格 | ❌ 结构混乱 | ✅ 完美保持 |

### 核心思想

**通过检测元素是否在表格中，应用不同的布局策略，既保持表格结构，又实现双语对照。**
