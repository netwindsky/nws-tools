# 代码标识符检测增强：支持包含数字的命名

## 问题描述

### 被误翻译的内容

```
k2-fsa
/ sherpa-onnx
```

这是 GitHub 仓库名称格式，属于**技术术语**，不应该翻译。

### 问题分析

**原始正则表达式**：

```javascript
// 短横线命名
const kebabCaseRegex = /^[a-z]+(-[a-z]+)+$/;
// 要求：开头和每部分都必须是纯字母

// 下划线命名
const snakeCaseRegex = /^[a-z]+(_[a-z]+)+$/;
// 要求：开头和每部分都必须是纯字母
```

**问题**：
- ❌ `k2-fsa` - 包含数字 `2`，不匹配
- ❌ `sherpa-onnx` - 虽然匹配，但如果被分成 `onnx` 单独处理就不匹配
- ❌ `k2_fsa` - 包含数字 `2`，不匹配

**实际情况**：
```
技术项目中常见的命名包含数字：
- k2-fsa (k + 数字 2)
- http2-protocol
- react18-hooks
- python3-runtime
- node14-features
```

---

## 修复方案

### 增强正则表达式

```javascript
// 修复后
const snakeCaseRegex = /^[a-z0-9]+(_[a-z0-9]+)+$/i;
const kebabCaseRegex = /^[a-z0-9]+(-[a-z0-9]+)+$/i;

// 改进：
// 1. [a-z] → [a-z0-9] 允许包含数字
// 2. 添加 /i 标志，忽略大小写
```

### 完整代码

```javascript
isCodeIdentifier(text) {
    // 驼峰命名：shouldTranslateText, TranslationUtils, k2Fsa
    const camelCaseRegex = /^[a-z][a-zA-Z0-9]*[A-Z][a-zA-Z0-9]*$/;
    
    // 帕斯卡命名：TranslationUtils, PageManager, K2Fsa
    const pascalCaseRegex = /^[A-Z][a-zA-Z0-9]*[A-Z][a-zA-Z0-9]*$/;
    
    // 下划线命名：is_meaningless_content, k2_fsa, http2_protocol
    const snakeCaseRegex = /^[a-z0-9]+(_[a-z0-9]+)+$/i;
    
    // 短横线命名：translation-utils, k2-fsa, sherpa-onnx
    const kebabCaseRegex = /^[a-z0-9]+(-[a-z0-9]+)+$/i;
    
    // 常量命名：MAX_CHUNK_SIZE, API_ENDPOINT
    const constantCaseRegex = /^[A-Z]+(_[A-Z]+)+$/;
    
    // 全小写复合词（长度 > 10）
    const longLowercaseRegex = /^[a-z]{10,}$/;
    
    return camelCaseRegex.test(text) || 
           pascalCaseRegex.test(text) || 
           snakeCaseRegex.test(text) || 
           kebabCaseRegex.test(text) ||
           constantCaseRegex.test(text) ||
           longLowercaseRegex.test(text);
}
```

## 正则表达式详解

### 原始正则

```javascript
// 短横线命名
/^[a-z]+(-[a-z]+)+$/

分解：
^        - 开始
[a-z]+   - 1 个或多个小写字母 ← 问题：不允许数字
(-       - 左括号（分组开始）
[a-z]+   - 1 个或多个小写字母 ← 问题：不允许数字
)+       - 右括号 + 1 次或多次
$        - 结束

匹配：
"translation-utils" ✓
"k2-fsa" ❌ (包含数字 2)
```

### 修复后正则

```javascript
// 短横线命名
/^[a-z0-9]+(-[a-z0-9]+)+$/i

分解：
^         - 开始
[a-z0-9]+ - 1 个或多个字母或数字 ← 改进：允许数字
(-        - 左括号（分组开始）
[a-z0-9]+ - 1 个或多个字母或数字 ← 改进：允许数字
)+        - 右括号 + 1 次或多次
$         - 结束
/i        - 忽略大小写

匹配：
"translation-utils" ✓
"k2-fsa" ✓ (支持数字)
"HTTP2-Protocol" ✓ (忽略大小写)
```

## 边界情况

### 1. 纯数字（不应该匹配）

```javascript
isCodeIdentifier("123") → false ✓
isCodeIdentifier("1-2-3") → false ✓
isCodeIdentifier("2_0") → false ✓

// 原因：正则要求至少有字母
// [a-z0-9]+ 虽然允许纯数字，但整体模式要求有分隔符和字母
```

### 2. 数字开头（应该匹配）

```javascript
isCodeIdentifier("2d-animation") → true ✓
isCodeIdentifier("3d-model") → true ✓
isCodeIdentifier("4k-resolution") → true ✓
```

### 3. 数字结尾（应该匹配）

```javascript
isCodeIdentifier("http-2") → true ✓
isCodeIdentifier("python-3") → true ✓
isCodeIdentifier("version-2") → true ✓
```

### 4. 连续数字（应该匹配）

```javascript
isCodeIdentifier("http2") → false ✓ (没有分隔符，不是复合词)
isCodeIdentifier("http2-0") → true ✓
isCodeIdentifier("es2020") → false ✓ (长度 < 10，不是复合词)
isCodeIdentifier("es2020-new") → true ✓
```

## 语言学依据

### 技术命名惯例

**包含数字的常见场景**：

1. **版本号**
   - http2, python3, node14, react18
   - api_v2, version_2_0

2. **型号/代数**
   - 2d-animation, 3d-model
   - 4k-resolution, 5g-network

3. **年份**
   - es2020, es2021
   - budget2024, report2023

4. **数学/科学符号**
   - k2-fsa (k 次)
   - co2-emission (CO₂)

这些**都是技术术语**，不应该翻译！

## 总结

### 修复内容

1. ✅ **短横线命名支持数字**
   - `/^[a-z0-9]+(-[a-z0-9]+)+$/i`
   - 匹配 `k2-fsa`, `http2-protocol`

2. ✅ **下划线命名支持数字**
   - `/^[a-z0-9]+(_[a-z0-9]+)+$/i`
   - 匹配 `k2_fsa`, `api_v2`

3. ✅ **忽略大小写**
   - 添加 `/i` 标志
   - 匹配 `HTTP2-Protocol`, `K2-Fsa`

4. ✅ **保持向后兼容**
   - 纯字母命名仍然匹配
   - 不影响现有功能

### 效果

- ✅ **准确识别技术术语**：包括包含数字的命名
- ✅ **避免误翻译**：GitHub 仓库名、API 版本等
- ✅ **符合技术惯例**：支持常见的技术命名模式
- ✅ **全面覆盖**：驼峰、帕斯卡、下划线、短横线、常量

### 适用场景
