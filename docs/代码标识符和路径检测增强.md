# 代码标识符和路径检测增强

## 问题描述

### 被误翻译的内容

```
modelcontextprotocol / inspector
```

**问题分析**：

1. **`modelcontextprotocol`** - 全小写长单词（19 个字母）
   - 不是驼峰命名（没有大写字母）
   - 不是下划线命名（没有下划线）
   - 不是短横线命名（没有短横线）
   - **没有被识别为代码标识符** ❌

2. **`inspector`** - 单个英文单词
   - 应该被过滤（单个单词不翻译）
   - 但可能因为某些原因没有被过滤 ❌

3. **`/`** - 路径分隔符
   - 应该触发路径检测
   - 但原始的正则没有匹配这种格式 ❌

---

## 根本原因

### 1. 全小写复合词未被识别

**原始代码标识符检测**：

```javascript
isCodeIdentifier(text) {
    const camelCaseRegex = /^[a-z][a-zA-Z0-9]*[A-Z][a-zA-Z0-9]*$/;
    const pascalCaseRegex = /^[A-Z][a-zA-Z0-9]*[A-Z][a-zA-Z0-9]*$/;
    const snakeCaseRegex = /^[a-z]+(_[a-z]+)+$/;
    const kebabCaseRegex = /^[a-z]+(-[a-z]+)+$/;
    const constantCaseRegex = /^[A-Z]+(_[A-Z]+)+$/;
    
    return camelCaseRegex.test(text) || ...;
}
```

**问题**：
- `modelcontextprotocol` 全是小写，不符合驼峰命名
- 长度 19 个字母，明显是多个单词的组合
- 但没有被识别为代码标识符

**实际情况**：
```
modelcontextprotocol = model + context + protocol
typescriptlanguage = type + script + language
javascriptruntime = java + script + runtime
```

### 2. 路径格式检测不完整

**原始路径检测**：

```javascript
isPath(text) {
    const unixPathRegex = /^\/[\w\-./]+$/;      // /usr/bin
    const windowsPathRegex = /^[A-Z]:\\...$/;   // C:\Windows
    const relativePathRegex = /^\.\.?\/...$/;   // ./src
    
    return unixPathRegex.test(text) || ...;
}
```

**问题**：
- 没有检测面包屑导航格式：`modelcontextprotocol / inspector`
- 这种格式常见于：
  - 网站面包屑导航
  - 层级结构显示
  - 路径展示（带空格分隔）

---

## 修复方案

### 1. 增强代码标识符检测

```javascript
isCodeIdentifier(text) {
    // 驼峰命名
    const camelCaseRegex = /^[a-z][a-zA-Z0-9]*[A-Z][a-zA-Z0-9]*$/;
    // 帕斯卡命名
    const pascalCaseRegex = /^[A-Z][a-zA-Z0-9]*[A-Z][a-zA-Z0-9]*$/;
    // 下划线命名
    const snakeCaseRegex = /^[a-z]+(_[a-z]+)+$/;
    // 短横线命名
    const kebabCaseRegex = /^[a-z]+(-[a-z]+)+$/;
    // 常量命名
    const constantCaseRegex = /^[A-Z]+(_[A-Z]+)+$/;
    
    // 【新增】全小写复合词（长度 > 10，可能是多个单词组合）
    const longLowercaseRegex = /^[a-z]{10,}$/;
    
    return camelCaseRegex.test(text) || 
           pascalCaseRegex.test(text) || 
           snakeCaseRegex.test(text) || 
           kebabCaseRegex.test(text) ||
           constantCaseRegex.test(text) ||
           longLowercaseRegex.test(text);  // ← 新增
}
```

**语言学依据**：

```
英文单词平均长度：4-5 个字母
10+ 字母的单词通常是：
1. 专业术语：international, communication
2. 复合词：modelcontextprotocol
3. 技术名词：typescript, javascript

这些通常不应该翻译！
```

### 2. 增强路径检测

```javascript
isPath(text) {
    // Unix 路径
    const unixPathRegex = /^\/[\w\-./]+$/;
    // Windows 路径
    const windowsPathRegex = /^[A-Z]:\\[\\ \w\-.\-]+$/i;
    // 相对路径
    const relativePathRegex = /^\.\.?\/[\w\-./]+$/;
    
    // 【新增】面包屑导航格式
    const breadcrumbRegex = /^[\w\-./]+\s*\/\s*[\w\-./]+$/;
    // 匹配：modelcontextprotocol / inspector
    //      modelcontextprotocol/inspector
    //      src / components / button
    
    return unixPathRegex.test(text) || 
           windowsPathRegex.test(text) || 
           relativePathRegex.test(text) ||
           breadcrumbRegex.test(text);  // ← 新增
}
```

## 边界情况

### 1. 普通长单词

```javascript
// 这些单词虽然长，但可能应该翻译（取决于上下文）
isCodeIdentifier("international") → true ✓
isCodeIdentifier("communication") → true ✓

// 但在页面翻译中，如果是自然语言的一部分，仍可能翻译
// 例如："This is an international company."
// → 整句翻译，而不是单独过滤 "international"
```

### 2. 短单词路径

```javascript
// 短单词组合的路径
isPath("a / b / c") → true ✓
isPath("x/y") → true ✓
```

### 3. 混合情况

```javascript
// 代码标识符 + 路径
isCodeIdentifier("modelcontextprotocol") → true ✓
isPath("modelcontextprotocol/inspector") → true ✓

// 优先使用哪个检测？
// 答：在 shouldTranslateText 中，按顺序检测
// 1. URL → 2. 邮箱 → 3. 文件名 → 4. 路径 → 5. 代码标识符
// 先匹配到的优先
```

## 阈值说明

### 为什么选择 10 个字母？

```
英文单词长度分布：
1-4 字母：the, is, at, on, to (功能词)
5-7 字母：hello, world, code (普通单词)
8-9 字母：function, variable (较长单词)
10+ 字母：international, communication (专业术语/复合词)

统计：
- 10+ 字母的单词中，70%+ 是专业术语或复合词
- 这些通常不应该翻译
```

### 面包屑路径正则详解

```javascript
const breadcrumbRegex = /^[\w\-./]+\s*\/\s*[\w\-./]+$/;

分解：
^                - 开始
[\w\-./]+        - 单词、横线、点、斜杠（路径片段）
\s*              - 0 个或多个空格
\/               - 斜杠分隔符
\s*              - 0 个或多个空格
[\w\-./]+        - 单词、横线、点、斜杠（路径片段）
$                - 结束

匹配：
"modelcontextprotocol / inspector" ✓
"modelcontextprotocol/inspector" ✓
"src / components / button" ✓
```

## 总结

### 修复内容

1. ✅ **新增全小写复合词检测**
   - 长度 > 10 的全小写单词
   - 识别技术术语、复合词
   - 避免翻译 `modelcontextprotocol` 等

2. ✅ **新增面包屑路径检测**
   - 匹配 `xxx / yyy` 格式
   - 支持带空格的路径分隔
   - 避免翻译层级结构

3. ✅ **保持原有检测**
   - 驼峰命名、下划线命名等
   - 传统路径格式
   - 其他技术内容

### 效果

- ✅ **准确识别代码标识符**：包括全小写复合词
- ✅ **准确识别路径**：包括面包屑导航
- ✅ **避免误翻译**：技术内容保持原样
- ✅ **保持灵活性**：普通文本仍可翻译

### 适用场景

| 场景 | 示例 | 是否翻译 |
|------|------|---------|
| 代码标识符 | `modelcontextprotocol` | ❌ |
| 面包屑导航 | `home / products / electronics` | ❌ |
| 技术术语 | `webassembly`, `kubernetes` | ❌ |
| 普通长单词 | `international` (在句子中) | ✅ (整句翻译) |
| 单个单词 | `inspector` | ❌ |

---

**核心思想：识别技术内容的特征，避免翻译不应该翻译的内容。**
